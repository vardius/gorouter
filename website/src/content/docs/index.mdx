## What you get

<CardGrid>
	<Card title="Zero-allocation matching" icon="rocket">
		Matching, middleware chains and finding no route allocate nothing. On fasthttp, neither do params or mounts.
	</Card>
	<Card title="Standard handlers" icon="approve-check">
		Any `http.Handler`, the usual `func(http.Handler) http.Handler` middleware, and params read with
		the standard `r.PathValue`.
	</Card>
	<Card title="Params and regexps" icon="random">
		`{id}` matches a segment, `{id:[0-9]+}` only one the regexp matches. Literals win, and a failed
		branch falls back to the next.
	</Card>
	<Card title="Scoped middleware" icon="puzzle">
		Around the whole router, the routes below a path, or one method below a path. Composed once at
		registration.
	</Card>
	<Card title="Mounting" icon="list-format">
		Hand a path to a sub-router or a file server. It sees paths relative to the mount, and mount params
		stay readable.
	</Card>
	<Card title="Correct by default" icon="information">
		405 with an `Allow` header, automatic `OPTIONS`, custom methods, and clear panics for invalid
		patterns.
	</Card>
</CardGrid>

## Coming from v4

<div class="landing-lead">
	The patterns stay the same. The API around them is smaller: options instead of setters, the standard
	`r.PathValue` instead of a params type, and a `fastrouter` package for fasthttp.
</div>

<div class="compare">

```go title="v4"
router := gorouter.New(logger)
router.GET("/hello/{name}", http.HandlerFunc(
	func(w http.ResponseWriter, r *http.Request) {
		params, _ := context.Parameters(r.Context())
		fmt.Fprintf(w, "hello, %s!", params.Value("name"))
	},
))
router.USE(http.MethodGet, "/admin", auth)
```

```go title="v5"
router := gorouter.New(gorouter.WithMiddleware(logger))
router.GET("/hello/{name}",
	func(w http.ResponseWriter, r *http.Request) {
		fmt.Fprintf(w, "hello, %s!", r.PathValue("name"))
	},
)
router.UseMethod(http.MethodGet, "/admin", auth)
```
